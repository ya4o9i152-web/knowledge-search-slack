# 開発者向け引き継ぎ

次にこのシステムを触る開発者向けです。設計の経緯は [スコープ.md](../スコープ.md)、未検証の点は [納品チェックリスト.md](../納品チェックリスト.md) にあります。

## 構成

| 場所 | 役割 |
|---|---|
| `src/app/api/slack/events/route.ts` | Slackの受け口。本体は `src/lib/slack-events.ts` |
| `src/app/api/cron/ingest/route.ts` | 定期取り込み（毎日）。本体は `src/lib/scheduled-ingest.ts` |
| `src/app/api/cron/audit-report/route.ts` | 監査ログの月次レポート。本体は `src/lib/audit-report.ts` |
| `src/lib/pipeline.ts` | 質問から回答まで（ユーザーの引き当て → 検索 → 要約 → ログ） |
| `src/lib/search.ts` / `answer.ts` | 検索（＋監査ログ）／Claudeによる要約 |
| `src/lib/extract.ts` / `chunking.ts` / `document-metadata.ts` / `ingest.ts` | 取り込み |
| `src/lib/document-source.ts` | 取り込み元（いまはSupabase Storage） |
| `src/lib/supabase-admin.ts` / `supabase-user.ts` | サービスロールの接続／質問者本人としての接続 |
| `supabase/schema.sql`、`supabase/migrations/` | テーブル、RLS、検索関数、監査、完全削除 |

## 設計上の約束ごと（壊すと事故になるもの）

1. **文書の検索にサービスロールを使わない**。検索は必ず `createUserClient` の接続で行う。サービスロールはRLSを素通りする。
2. **検索は `search_documents_logged` を呼ぶ**。`match_document_chunks` を直接呼ぶと、監査ログが残らない。
3. **文書を消すときは `delete_document_with_redaction` を使う**。テーブルから直接消すと、監査ログに参照が残り、取り込み元にファイルがあれば翌日に復活する。
4. **部署を読み取れない文書は取り込まない**。推測で部署を埋めない。
5. **出典をClaudeに書かせない**。Claudeが返すのは文書と箇所の番号だけ。
6. **Embeddingの呼び出しは `src/lib/embeddings.ts` だけ**。送信先を差し替えるときに直すのはこの1ファイル。次元数（1536）を変えるときは、スキーマの `vector(1536)` と全チャンクの再作成が必要。
7. **Slackの受け口は、3秒以内に応答を返す**。同期でやるのは署名の検証・重複の確認・後処理の登録だけ。
8. **チャンネルに回答を出さない**。閲覧制限のある内容は、質問した本人のDMにだけ送る。

## コマンド

| コマンド | 内容 | 費用 |
|---|---|---|
| `npm run verify:schema` | スキーマと閲覧制限を、手元の組み込みPostgresで検証 | なし |
| `npm run test:chunking` | 抽出・正規化・チャンキングのテスト | なし |
| `npm run test:slack` | Slack受信のテスト（最後の1項目だけClaudeを2回呼ぶ） | わずか |
| `npm run check:connections` | 各サービスへの接続確認 | わずか |
| `npm run seed:users` / `check:rls` | テストユーザーの登録／本番での閲覧制限の検証 | なし |
| `npm run ingest [-- --dry-run / --limit N / --dir <フォルダ>]` | 手元のフォルダからの一括取り込み | Embedding |
| `npm run check:recall` / `check:answers` | 検索精度／12問の回答の検証 | Embedding／Claude 12回 |
| `npm run ask -- "質問" --user <key>` | テストユーザーとして1問だけ試す | Claude 1回 |
| `npm run incoming -- setup / upload / list / run` | 取り込み待ちの置き場所の操作、定期取り込みの手動実行 | Embedding |
| `npm run register:user -- <SlackID> "<氏名>" <部署,…>` | 利用者の所属の登録・変更 | なし |
| `npm run admin -- documents / restrict / set-department / delete / audit / report` | 機密文書の取り扱いと監査ログ | なし |

確認用コマンドからの検索は、監査ログの経路が `cli` になり、月次レポートには数えられません。

## 環境変数

`.env.example` を参照。Vercelの本番環境にも同じ値を登録しています（`vercel env ls production`）。

- `SUPABASE_SERVICE_ROLE_KEY`：閲覧制限を素通りできるキー。持つ人を最小限にする
- `CRON_SECRET`：定期実行の受け口の保護。Vercel Cronが自動で付ける
- `INGEST_NOTIFY_CHANNEL`：取り込み結果と月次レポートの通知先（SlackのチャンネルIDかユーザーID）

## よくある作業

| 作業 | 方法 |
|---|---|
| スキーマを変える | `supabase/migrations/` に番号つきのSQLを足す（何度実行しても通るように書く）→ `npm run verify:schema` → 本番のSQL Editorで実行 → **そのあとで**コードをデプロイ |
| デプロイする | `vercel deploy --prod`。直後は古いデプロイが応答することがあるので、数秒おいて確認する |
| 本番のエラーを見る | `vercel logs knowledge-search-slack.vercel.app --since 10m` |
| プロンプトを変える | `src/lib/answer.ts` の `SYSTEM_PROMPT` → `npm run check:answers` で12問を再確認 |
| チャンクの大きさを変える | `src/lib/chunking.ts` の定数 → `npm run test:chunking` → 全文書の取り込み直しが必要 |

## これまでにはまった点

| 症状 | 原因と対処 |
|---|---|
| 部署で絞ると、20件要求して4件しか返らない | HNSWは近傍を取り出した後に条件を適用する。検索関数に `hnsw.iterative_scan = relaxed_order` を設定（pgvector 0.8以降） |
| 「銀行」で検索しても一致しない／部署「人事」を判定できない | PDFから取り出した漢字が、見た目の同じ部首用の文字になっている。`src/lib/text-normalize.ts` で戻す。質問文にも同じ処理をかける |
| 本番でだけ、取り込みの受け口が500になる（`DOMMatrix is not defined`） | pdf-parseの部品がバンドルで読み込めない。`next.config.ts` の `serverExternalPackages` と `outputFileTracingIncludes` |
| Slackで文書名の前後に `*` が表示される | 太字の記号は、直後が全角の文字だと効かない。rich_text ブロックで指定する |
| `/invite @knowledge` に回答が返る | スラッシュコマンドが発言として届く。スラッシュで始まる発言は無視する |
| 文書側のRLSポリシーを書いたのに、何も見えない | ポリシーが参照する `user_departments` にも「自分の行だけ読める」ポリシーが必要 |
