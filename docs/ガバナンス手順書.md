# 機密文書の取り扱いガバナンス手順書

ナレッジ検索AIに取り込んだ文書を、安全に運用するための手順です。ナレッジご担当者様と、情報システムご担当者様を対象にしています。

操作は、管理者の端末でコマンドを実行して行います（管理画面はありません）。コマンドは `案件７` のフォルダで実行します。

## この手順書で答える質問

| 質問 | 見る場所 |
|---|---|
| うっかり機密度の高い文書を取り込んでしまった。取り消せるか | ②完全に削除する |
| この文書は、限られた人だけに見せたい | ①機密扱いに変更する |
| 誰が何を検索したか、後から確認できるか | ③監査ログを確認する |
| 異動・退職があった。閲覧できる範囲はどう変えるか | ④所属を変更する |
| 文書はいつ検索できるようになるか。取り込めなかった文書はどうなるか | ⑤毎日の自動取り込み |

## はじめに：閲覧のしくみ

- 文書には、1つの部署（戦略／業務／IT／人事／営業／管理）か、「機密」の区分が付きます。
- 社員には、所属する部署と区分を登録します。兼務の場合は複数を登録できます。
- 社員が検索できるのは、自分の所属と同じ部署・区分の文書だけです。それ以外の文書は、存在も含めて表示されません。
- 文書の部署は、文書の冒頭の「部署:」の行から読み取ります。部署を読み取れない文書は取り込まれません。

## ① 機密扱いに変更する

特定の文書を、限られた人だけが検索できるようにします。文書は削除されません。

1. 文書のIDを調べる。
   ```
   npm run admin -- documents
   ```
2. 文書を機密扱いにする。
   ```
   npm run admin -- restrict <文書ID>
   ```
3. 機密の文書を見てよい人に、「機密」の区分を追加する（すでに登録済みなら不要）。
   ```
   npm run register:user -- <SlackユーザーID> "<氏名>" 戦略,機密
   ```

- 変更はすぐに反映されます。以後、元の部署の人が検索しても、その文書は出てきません。
- 元に戻すときは、`npm run admin -- set-department <文書ID> <部署>` で元の部署を指定します。
- 機密扱いにする前に検索された記録は、監査ログに残ります。誰の検索に出ていたかは、③の `--document` で確認できます。

## ② 完全に削除する

取り込むべきでなかった文書を、検索できない状態にし、記録からも参照を消します。**元に戻せません。**

1. 先に、その文書が誰の検索に出ていたかを確認する（削除すると参照が消えるため、必要なら控えておく）。
   ```
   npm run admin -- audit --document <文書ID>
   ```
2. 文書を完全に削除する。理由は必ず書く。
   ```
   npm run admin -- delete <文書ID> "契約上、取り込み不可の文書だった"
   ```
3. 保管場所（SharePoint）にある原本を、必要に応じて削除または移動する。

手順2の1回の操作で、次の4つがまとめて行われます。途中で失敗した場合は、何も変わりません。

| 行われること | 内容 |
|---|---|
| 文書の削除 | 文書と、検索用に分割した本文をすべて削除する |
| 監査ログからの参照の削除 | 過去の検索記録から、この文書への参照を取り除く。取り除いた数は記録に残る |
| 再取り込みの防止 | 原本が保管場所に残っていても、毎日の自動取り込みで読み飛ばす |
| 削除の記録 | いつ・どの保管場所の文書を・どんな理由で削除したかを残す（文書名は残さない） |

削除しても残るものが2つあります。

- **質問文**：「誰が・いつ・何を質問したか」の記録は消しません。質問文そのものに機密の内容が書かれていないかは、③で確認してください。
- **Slackに届いた回答**：すでにSlackに表示された要約は、このシステムからは消せません。該当する人に、Slack上のメッセージの削除を依頼してください。対象者は手順1で分かります。

## ③ 監査ログを確認する

検索のたびに、次の内容が記録されます。記録できなかった場合は、回答そのものが返りません。

| 記録する内容 | 例 |
|---|---|
| 誰が | SlackユーザーID、検索した時点の所属 |
| いつ | 日時 |
| 何を質問したか | 質問文 |
| どの文書が取り出されたか | AIに渡した文書と、その箇所 |
| どの文書が回答に使われたか | 回答に挙げた文書 |
| 結果 | 回答あり／該当なし／所属が未登録／エラー |

確認するコマンドです。

```
npm run admin -- audit                              直近50件
npm run admin -- audit --user <SlackユーザーID>      特定の人の検索
npm run admin -- audit --since 2026-10-01           指定した日以降
npm run admin -- audit --document <文書ID>           特定の文書が出た検索
npm run admin -- report 2026-10                     月ごとの利用状況
```

- **月次レポート**：毎月1日に、先月の利用状況がSlackに届きます。部署別の質問数・利用者数と、「該当なし」が多かった質問が載ります。
- **「該当なし」が多い質問**は、文書が足りていない分野の手がかりです。取り込む文書の見直しに使えます。
- **所属が未登録の利用者**が出ていたら、④で登録してください。

## ④ 所属を変更する（異動・兼務・退職）

所属を登録し直すと、すぐに検索できる範囲が変わります。指定した内容で上書きされます。

```
npm run register:user -- <SlackユーザーID> "<氏名>" 人事            異動（人事だけになる）
npm run register:user -- <SlackユーザーID> "<氏名>" 戦略,IT         兼務
npm run register:user -- <SlackユーザーID> "<氏名>" ""              退職・利用停止（何も検索できなくなる）
```

SlackユーザーIDは、Slackでその人のプロフィールを開き、「…」→「メンバーIDをコピー」で確認できます。

- 所属が未登録の人が質問すると、「所属部署が登録されていないため、検索できません」と返ります。
- 所属を変えても、過去の検索記録の所属は変わりません（検索した時点の所属が残ります）。

## ⑤ 毎日の自動取り込み

- 毎日 午前2時に、保管場所に追加された新しいPDF・Wordを取り込みます。追加の翌日から検索できます。
- 取り込みか失敗があった日は、結果がSlackに届きます。何もなかった日は届きません。
- 取り込めなかった文書は、毎日もう一度試されます。原因を直すか、保管場所から取り除くまで、毎日通知が届きます。

| 通知の内容 | 対応 |
|---|---|
| 「部署:」の行がありません | 文書の冒頭に「部署: 戦略 / 客先: … / 作成: 2025年 / 機密度: 社外秘」の行を入れる |
| 部署「◯◯」は登録された6部署にありません | 部署名を、戦略／業務／IT／人事／営業／管理のいずれかに直す |
| テキストを抽出できませんでした | 紙をスキャンしたPDFの可能性。文字を選択できるPDFに作り直す |
| 制限時間のため◯件は次回に回りました | 対応は不要。翌日以降に続きから取り込まれる |

対応していないことが2つあります。

- **差し替え**：同じ場所のファイルを新しい内容に差し替えても、検索には反映されません。②で古い文書を削除し、別のファイル名で置き直してください。
- **PowerPoint**：取り込まれません（次の段階で対応予定）。

## やってはいけないこと

- **管理者用のキー（サービスロールのキー）を共有しない**：閲覧の制限をすべて素通りできます。持つ人を最小限にしてください。
- **データベースを直接編集して文書を消さない**：監査ログの参照と再取り込みの防止が行われません。必ず②のコマンドを使ってください。
- **AIの要約だけで判断しない**：要約は100%正確ではありません。重要な判断の前に、出典から原本を確認してください。
